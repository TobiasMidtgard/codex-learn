## A program is a list of instructions

Python reads your file from the top and does what each line says, one line at a time. That is the whole trick. Everything else — loops, functions, classes — is a way of organising those instructions.

```python
print("Hello, world")
print("This runs second")
```

`print()` writes whatever is inside the parentheses to the screen. The text in quotes is called a **string**.

## Comments

A line that starts with `#` is a comment. Python ignores it completely; it exists for the humans reading the code.

```python
# Explain *why* the code does something, not what it does.
total = price * 1.25  # price including 25% VAT
```

## Strings and numbers are different things

```python
print("40" + "2")   # 402  — joins two strings together
print(40 + 2)       # 42   — adds two numbers
print(7 * 6)        # 42   — Python does the maths, then prints the result
```

Quotes make a string. No quotes makes a number (or a name — more on that next lesson). Mixing them is one of the first errors everyone meets:

```python
print("Total: " + 42)   # TypeError: can only concatenate str (not "int") to str
```

## Errors are normal

When Python cannot follow an instruction it stops and prints a **traceback**:

```text
Traceback (most recent call last):
  File "main.py", line 3, in <module>
    print(nmae)
NameError: name 'nmae' is not defined
```

Read it from the bottom: the last line names the error and explains it. The line above points to where it happened. You will read hundreds of these — they are Python helping you, not judging you.

## Variables are names for values

A variable is a label you stick on a value so you can use it later.

```python
price = 120.0
quantity = 2
subtotal = price * quantity
print(subtotal)   # 240.0
```

Names can contain letters, digits and underscores, and cannot start with a digit. By convention Python uses `snake_case`: `total_price`, not `TotalPrice`. Constants that never change are written in capitals: `TAX_RATE = 0.25`.

## Every value has a type

| Type | Example | What it is for |
|---|---|---|
| `int` | `42` | whole numbers |
| `float` | `3.14` | numbers with decimals |
| `str` | `"hello"` | text |
| `bool` | `True`, `False` | yes/no answers |

`type()` tells you which one you have, and you can convert between them:

```python
print(type(42))          # <class 'int'>
print(int("12") + 3)     # 15   — string to int
print(str(12) + "3")     # 123  — int to string
print(float("2.5") * 2)  # 5.0
```

## Arithmetic

```python
print(10 + 3)    # 13
print(10 - 3)    # 7
print(10 * 3)    # 30
print(10 / 3)    # 3.3333333333333335  — division always gives a float
print(10 // 3)   # 3   — floor division: whole part only
print(10 % 3)    # 1   — modulo: the remainder
print(2 ** 10)   # 1024 — power
```

`%` looks odd but is everywhere: `n % 2 == 0` is how you check whether a number is even.

## f-strings: putting values inside text

Put an `f` before the opening quote and any expression inside `{}` is evaluated and inserted:

```python
name = "Ada"
items = 3
print(f"{name} bought {items} items")          # Ada bought 3 items
print(f"Next year she'll have {items + 1}")    # expressions work too
print(f"Total: {240.0:.2f} kr")                # Total: 240.00 kr  — format with 2 decimals
```

`:.2f` means "as a float with 2 decimals". You will use it for money constantly.

## A few string methods

```python
s = "  Wiper Blades  "
print(s.strip())          # "Wiper Blades"   — remove surrounding whitespace
print(s.lower())          # "  wiper blades  "
print(s.upper())
print(s.strip().replace("Blades", "Fluid"))
print(len("hello"))       # 5
print("a,b,c".split(","))  # ['a', 'b', 'c']
print("hello"[0])         # h    — index from 0
print("hello"[1:3])       # el   — slice: start included, end excluded
```

> **Rule of thumb:** methods are called *on* a value with a dot (`s.upper()`), functions take the value as an argument (`len(s)`).

## Decisions: if, elif, else

```python
temperature = 23

if temperature > 28:
    print("Hot")
elif temperature > 18:
    print("Nice")
else:
    print("Cold")
```

The block that runs is the first one whose condition is `True`. Everything indented under the `if` belongs to it — **indentation is how Python knows where a block starts and ends**. Four spaces is the convention.

Comparisons produce booleans:

| Operator | Meaning |
|---|---|
| `==` `!=` | equal, not equal (note: `=` is assignment, `==` is comparison) |
| `<` `>` `<=` `>=` | less / greater than (or equal) |
| `and` `or` `not` | combine conditions |
| `in` | membership: `"a" in "cat"`, `3 in [1, 2, 3]` |

```python
age = 20
has_licence = True
if age >= 18 and has_licence:
    print("Can rent a car")
```

Empty things count as `False`: `""`, `[]`, `0` and `None` are all "falsy". So `if name:` means "if name is not empty".

## Repeating work: for

A `for` loop runs a block once for each item in a sequence.

```python
for tool in ["wrench", "jack", "torch"]:
    print("Pack the", tool)

for i in range(5):        # 0, 1, 2, 3, 4  — stop is not included
    print(i)

for i in range(2, 10, 3): # 2, 5, 8       — start, stop, step
    print(i)
```

The accumulator pattern shows up everywhere:

```python
total = 0
for n in [4, 8, 15]:
    total += n         # same as total = total + n
print(total)           # 27
```

`enumerate` gives you the index and the item together:

```python
for index, name in enumerate(["Ada", "Linus"]):
    print(index, name)   # 0 Ada, 1 Linus
```

## Repeating while a condition holds

```python
attempts = 0
while attempts < 3:
    print("Trying...")
    attempts += 1
```

If the condition never becomes `False` the loop never ends — in this browser that will freeze the page, so always make sure something inside the loop changes the condition.

## break and continue

```python
for n in [3, 8, -1, 5]:
    if n < 0:
        break          # leave the loop entirely
    if n % 2 == 0:
        continue       # skip the rest of this iteration
    print(n)           # prints 3, then stops at -1
```

> **Tip:** when logic gets tangled, write the conditions as English first: "if it is divisible by both, then by three, then by five, otherwise the number". The order of the checks matters.

def letter_grade(score):
    """Return "A", "B", "C", "D" or "F" for a score 0-100."""
    if score >= 90:
        return "A"
    elif score >= 80:
        return "B"
    elif score >= 70:
        return "C"
    elif score >= 60:
        return "D"
    return "F"


def count_grades(scores):
    """Return a dict with counts for every letter."""
    counts = {"A": 0, "B": 0, "C": 0, "D": 0, "F": 0}

        counts[letter_grade(score)] += 1
    return counts

## Functions: give a piece of work a name

A function packages a few lines of code so you can run them by name, as often as you like, with different inputs.

```python
def greet(name):
    return f"Hello, {name}!"

message = greet("Ada")   # call it; the result comes back
print(message)
print(greet("Linus"))
```

- `def` starts the definition, `name` is a **parameter** — a placeholder for whatever the caller passes in.
- `return` hands a value back to the caller *and* ends the function immediately.
- Defining a function runs nothing. Only calling it does.

## return is not print

`print` shows something to a human. `return` gives a value to the rest of your program. A function that only prints cannot be used in a calculation:

```python
def double(n):
    print(n * 2)       # shows 8, but returns None

result = double(4) + 1   # TypeError: None + 1
```

If a function has no `return`, it returns `None`. The checks in this platform call your functions and inspect the return value, so `return` is what they see.

## Defaults and keyword arguments

```python
def price_with_tax(price, rate=0.25):
    return price * (1 + rate)

print(price_with_tax(100))          # 125.0 — uses the default rate
print(price_with_tax(100, 0.15))    # 115.0
print(price_with_tax(rate=0.1, price=50))  # keywords can go in any order
```

## Scope: variables live inside the function

```python
def add_fee(total):
    fee = 20            # only exists inside this function
    return total + fee

print(add_fee(100))     # 120
print(fee)              # NameError — fee is gone
```

Read variables from outside freely, but pass values in as parameters instead of relying on globals. It makes functions testable and reusable.

## Early returns keep code flat

```python
def describe(n):
    if n < 0:
        return "negative"
    if n == 0:
        return "zero"
    return "positive"
```

## Returning more than one thing

```python
def min_max(numbers):
    return min(numbers), max(numbers)   # a tuple

low, high = min_max([4, 9, 1])          # unpack it
```

## Docstrings and type hints

```python
def area(width: float, height: float) -> float:
    """Return the area of a rectangle."""
    return width * height
```

Hints don't change how the code runs; they tell readers (and editors) what you intended.

    """Return a dict of lowercase word -> count."""
    counts = {}

def top_players(scores, n):
    """Return the n best (name, score) pairs, highest first, ties by name."""
    ranked = sorted(scores.items(), key=lambda pair: (-pair[1], pair[0]))
    return ranked[:n]


def average_score(scores):
    """Return the average score rounded to 1 decimal, or 0.0 if empty."""
    if not scores:
        return 0.0
    return round(sum(scores.values()) / len(scores), 1)

## Exceptions: how Python reports problems

When something goes wrong at runtime Python *raises an exception*. Unhandled, it crashes the program with a traceback. Handled, it becomes a normal part of the flow.

```python
try:
    number = int("abc")
except ValueError:
    print("That wasn't a number")
```

Catch the **specific** exception you expect. A bare `except:` swallows everything — including bugs you would rather know about.

## The full shape

```python
try:
    f = open("config.json")
except FileNotFoundError:
    print("No config yet, using defaults")
else:
    print("Loaded")      # runs only if no exception happened
finally:
    print("Done")        # runs no matter what — cleanup goes here
```

## Raising your own

Functions should refuse bad input loudly instead of returning nonsense:

```python
def withdraw(balance, amount):
    if amount <= 0:
        raise ValueError("Amount must be positive")
    if amount > balance:
        raise ValueError("Insufficient funds")
    return balance - amount
```

Callers can decide what to do:

```python
try:
    balance = withdraw(balance, 500)
except ValueError as err:
    print("Refused:", err)
```

## Common exceptions you will meet

| Exception | Typical cause |
|---|---|
| `NameError` | using a name that isn't defined (often a typo) |
| `TypeError` | wrong type: `"a" + 1`, calling something that isn't a function |
| `ValueError` | right type, bad value: `int("abc")` |
| `KeyError` | dictionary key that doesn't exist |
| `IndexError` | list index out of range |
| `ZeroDivisionError` | dividing by zero |
| `FileNotFoundError` | opening a path that doesn't exist |
| `AttributeError` | `thing.method()` where thing has no such method |

## Custom exceptions

```python
class OutOfStock(Exception):
    pass

raise OutOfStock("No more wiper blades")
```

Your own exception types let callers catch exactly your errors and nothing else.

> **Python's style is "ask forgiveness, not permission":** try the operation and handle the failure, rather than checking every precondition first.

class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.balance = balance

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("Deposit must be positive")
        self.balance += amount

    def withdraw(self, amount):
        if amount <= 0:
            raise ValueError("Withdrawal must be positive")
        if amount > self.balance:
            raise ValueError("Insufficient funds")
        self.balance -= amount

    def __str__(self):
        return f"{self.owner}: {self.balance:.2f} kr"


def safe_withdraw(account, amount):
    """Return True if the withdrawal succeeded, False if it was refused."""
    try:
        account.withdraw(amount)
        return True
    except ValueError:
        return False


acc = BankAccount("Ada", 100)
acc.deposit(50)
print(acc)
print(safe_withdraw(acc, 500))

## Classes: data and behaviour together

A class is a blueprint. Each object built from it has its own data (**attributes**) and shares the same behaviour (**methods**).

```python
class Car:
    wheels = 4                           # class attribute: shared by all cars

    def __init__(self, plate, km=0):     # runs when you create a Car
        self.plate = plate               # instance attributes: this car's data
        self.km = km

    def drive(self, distance):
        self.km += distance
        return self.km

    def __str__(self):                   # what print() shows
        return f"{self.plate} ({self.km} km)"


golf = Car("AB 12345")
golf.drive(120)
print(golf)          # AB 12345 (120 km)
```

`self` is the object the method was called on. Python passes it automatically: `golf.drive(120)` becomes `Car.drive(golf, 120)`.

A `@classmethod` receives the class instead of an instance — handy for alternative constructors like `Inventory.load(path)`. A `@property` makes a method look like an attribute.

## Modules: splitting code across files

Any `.py` file is a module. Import what you need:

```python
import math

```

Keep code that *defines things* (classes, functions) in modules and code that *runs things* in a `main.py`. The guard below lets a file be both importable and runnable:

```python
if __name__ == "__main__":
    main()
```

@@ py-5-1.solution.inventory.py
import json


class Item:
    def __init__(self, name, price, quantity):
        self.name = name
        self.price = price
        self.quantity = quantity


class Inventory:
    def __init__(self):
        self.items = {}   # name -> Item

    def add(self, item):
        existing = self.items.get(item.name)
        if existing:
            existing.quantity += item.quantity
        else:
            self.items[item.name] = item

    def remove(self, name, quantity):
        if name not in self.items:
            raise KeyError(name)
        item = self.items[name]
        if quantity > item.quantity:
            raise ValueError(f"Only {item.quantity} {name} in stock")
        item.quantity -= quantity
        if item.quantity == 0:
            del self.items[name]

    def find(self, query):
        q = query.lower()
        hits = [item for item in self.items.values() if q in item.name.lower()]
        return sorted(hits, key=lambda item: item.name)

    def total_value(self):
        return sum(item.price * item.quantity for item in self.items.values())

    def low_stock(self, threshold=5):
        hits = [item for item in self.items.values() if item.quantity < threshold]
        return sorted(hits, key=lambda item: item.name)

    def save(self, path):
        data = [
            {"name": i.name, "price": i.price, "quantity": i.quantity}
            for i in self.items.values()
        ]
        with open(path, "w") as f:
            json.dump(data, f)

    @classmethod
    def load(cls, path):
        inv = cls()
        with open(path) as f:
            for row in json.load(f):
                inv.add(Item(row["name"], row["price"], row["quantity"]))
        return inv

    def report(self):
        lines = [f"{'Item':<20}{'Qty':>5}{'Price':>10}"]
        for item in sorted(self.items.values(), key=lambda i: i.name):
            lines.append(f"{item.name:<20}{item.quantity:>5}{item.price:>10.2f}")
        lines.append(f"Total: {self.total_value():.2f}")
        return "\n".join(lines)

## What happens when you open a page

1. The browser asks a server for a URL.
2. The server answers with an **HTML** document.
3. The browser reads it and builds the **DOM** — a tree of elements it can draw and that JavaScript can change.
4. Linked **CSS** decides how it looks; linked **JavaScript** decides how it behaves.

You write the three languages; the browser combines them.

## HTML is made of elements

```html
<p class="intro">Wiper blades, <strong>fitted while you wait</strong>.</p>
```

- `<p>` is the opening tag, `</p>` the closing tag, everything between is the content.
- `class="intro"` is an **attribute**: extra information on the opening tag.
- Elements nest: the `<strong>` lives inside the `<p>`. Close them in the reverse order you opened them.

A few elements have no content and no closing tag: `<img>`, `<br>`, `<input>`.

## The skeleton every page has

```html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <title>Shown in the browser tab</title>
    <link rel="stylesheet" href="style.css">
  </head>
  <body>
    <\!-- everything visible goes here -->
  </body>
</html>
```

`<\!-- -->` is a comment.

## The elements you will use most

| Element | Job |
|---|---|
| `<h1>` … `<h6>` | headings; one `<h1>` per page, then `<h2>` for sections |
| `<p>` | a paragraph |
| `<a href="https://…">` | a link — `href` is where it goes |
| `<img src="photo.jpg" alt="…">` | an image; `alt` describes it for screen readers and when it fails to load |
| `<ul>` `<ol>` `<li>` | unordered / ordered lists and their items |
| `<button>` | something to click |
| `<input>` `<form>` `<label>` | collecting input |
| `<div>` `<span>` | generic boxes (block / inline) when nothing more specific fits |

## Semantic layout elements

Instead of a page of `<div>`s, describe the structure:

```html
<header>  site name, navigation </header>
<nav>     links </nav>
<main>    the page's actual content </main>
<section> a thematic group </section>
<article> a self-contained piece: a post, a product card </article>
<aside>   related but secondary </aside>
<footer>  contact, copyright </footer>
```

Screen readers, search engines and future-you all benefit.

## Attributes worth knowing

- `id="x"` — unique name for one element (JavaScript and CSS use it)
- `class="a b"` — reusable labels; an element can have many
- `alt`, `href`, `src`, `type`, `placeholder`, `disabled`

> **Open the developer tools** in your own browser (F12 or right-click → Inspect) and look at any page's Elements panel. Everything you see there is the DOM you are about to learn to build.

## Connecting CSS to HTML

```html
<link rel="stylesheet" href="style.css">
```

A stylesheet is a list of **rules**. Each rule picks elements with a *selector* and sets *properties*:

```css
h1 {
  color: #1b1f2a;
  font-size: 2rem;
}
```

## Selectors

| Selector | Matches |
|---|---|
| `p` | every `<p>` |
| `.card` | anything with `class="card"` |
| `#main-nav` | the one element with `id="main-nav"` |
| `.card h2` | an `<h2>` anywhere inside `.card` |
| `a:hover` | a link while the mouse is over it |
| `.card, .panel` | either |

When rules conflict, the more specific selector wins (`#id` beats `.class` beats `p`), and among equals the last one written wins.

## The box model

Every element is a box: **content**, wrapped in **padding**, wrapped in a **border**, wrapped in **margin** (space outside).

```css
.card {
  padding: 16px;          /* inside the border */
  border: 1px solid #ddd;
  margin: 24px auto;      /* outside; auto left/right centres a block with a width */
  max-width: 480px;
  border-radius: 12px;
  box-shadow: 0 6px 20px rgba(0, 0, 0, .08);
}
```

Add this once to every project and widths will behave the way you expect:

```css
* { box-sizing: border-box; }
```

## Colour and type

```css
body {
  font-family: system-ui, sans-serif;
  line-height: 1.5;
  color: #222;
  background: #f5f6f8;
}
```

Colours: named (`tomato`), hex (`#f26a1b`), `rgb(242, 106, 27)`, or with alpha `rgba(0,0,0,.1)`. Sizes: `px` for exact, `rem` for "relative to the base font size" (good for text), `%` for relative to the parent.

## Layout: flexbox

Flexbox lays out children in a row (or column) and makes alignment easy.

```css
nav {
  display: flex;
  justify-content: space-between;   /* spread along the main axis */
  align-items: center;              /* centre on the cross axis */
  gap: 16px;                        /* space between children */
}
.skills { display: flex; flex-wrap: wrap; gap: 8px; }
```

## Layout: grid

Grid is for two dimensions — columns *and* rows.

```css
.gallery {
  display: grid;
  grid-template-columns: repeat(3, 1fr);   /* three equal columns */
  gap: 12px;
}
```

## Responsive: react to screen size

```css
@media (max-width: 600px) {
  .gallery { grid-template-columns: 1fr; }
}
```

Rules inside a media query only apply when the condition holds. Start with the mobile layout and add columns as the screen grows, or the reverse — just pick one and be consistent.

## Custom properties

```css
:root { --accent: #f26a1b; }
button { background: var(--accent); }
```

Change the colour in one place, everything updates.
